# CDP Engine (`engines/cdp-engine`)

The [CDP-WASM-SUITE](https://github.com/cdp-wasm-suite) (a WASM port of the Composer's
Desktop Project) as **one consolidated WCLAP instrument** — the Airwindows-Consolidated
shape: a single `module.wasm` plus a "Program" parameter that selects among the catalog's
generator entries (16 curated entries over 9 CDP programs; the full 215-program suite is
reachable through the same host bridge). Written from scratch for this repo (MIT); the
vendored cdp-wasm assets under `third_party/cdp-wasm/` ship unmodified with their own
license — see `NOTICE`.

## Why a host bridge instead of CDP wasm inside the module

The cdp-wasm programs are Emscripten side modules that need their JS glue (MEMFS +
dynamic linking into a shared `cdp-core.wasm`) — that cannot run inside a standalone
wasm CLAP module. So the render happens in the host's JS via the vendored `cdp-wasm`
engine, and the result is handed back over a small import/export bridge, module
`wclap.cdp/1`:

- import `u32 render_request(u32 reqId, const char* spec, u32 specLen, i32 note, u32 vel7)` —
  called synchronously from `process()` on note-on; the host renders async and later calls
  the exported `cdp_deliver`. Hosts without the bridge answer ENOSYS and notes stay silent.
- export `void cdp_deliver(u32 reqId, float* planar, u32 frames, u32 chans, double rate, i32 baseKey)` —
  the host mallocs `planar` in the module's memory; ownership passes to the voice.

This mirrors how cdp-plugin itself works (render offline with CDP, play back through a
polyphonic sampler — cdp-sampler), and how our SFZ renditions and CPPN pre-rendered notes
work: **CDP is an offline toolkit, so in a rack it is a source (rendered per note) or an
offline stage at extract time** — never a realtime `process()` effect. The 232 curated
catalog effects are therefore applied offline over rendered audio through the bridge's
`applyEffectToWav` (rack extract, QD runs), not as CLAP audio-effect plugins.

- **Plugin**: `is.synth.kromosynth.cdp-engine` "Kromosynth CDP Engine", features
  `instrument` + `sampler`. No audio input, one stereo output; one note input port
  (CLAP dialect, raw MIDI also understood).
- **Spec JSON** sent per note: `{"i":programIndex,"dur":seconds,"root":midiKey,"p":[p1..p12]}`.
  Positional `p[]` maps onto the catalog entry's params by index (see `catalog.json`,
  generated by `scripts/make-catalog.mjs`); unset (`-1e9`) means catalog default. If the
  entry has a `freq` param, the bridge renders at the note's own frequency
  (`440 * 2^((note-69)/12)`, MIDI: key 69 = A4) and delivers `baseKey = note`; otherwise it
  renders at the root key and the voice pitch-shifts by `2^((key-baseKey)/12)`.
- **Voices**: fixed pool of 16, 4-point cubic Hermite (Catmull-Rom) interpolation (an
  original implementation — the LGPL cdp-sampler header is deliberately not vendored),
  note 60 = native rate convention from cdp-sampler. 5 ms attack, 80 ms release on
  note-off. A note whose buffer has not arrived yet stays silent until `cdp_deliver` lands
  (that render latency is real and reported, not hidden: `clap.latency` = 0, `clap.tail` =
  longest ringing voice).
- **Params**: 0 Volume dB; 1 Program (catalog generator index 0..255); 2 Duration s;
  3 Root key; 4..15 P1..P12 positional program params. **State**: binary round-trip of all.
- **wclap.files/1** frames accepted on clap.webview/3 (SPEC §8) with the same FNV-1a
  digest logging as sfz-engine (e.g. to deliver `catalog.json`); no editor page.

## Host integration

- `reference-host/cdp-bridge.mjs` — `CDPBridge`: loads the vendored cdp-wasm engine,
  serves `render_request` (serialized, cached by (program, params, note)), and delivers
  via `cdp_deliver`. Also exposes the offline paths `renderGeneratorToWav` /
  `applyEffectToWav` and a slim `catalog()` for UIs. Works in Node (file: pkgUrl) and the
  browser (http pkgUrl — `tools/serve.mjs` already serves the repo root, so
  `/wclap/engines/cdp-engine/third_party/cdp-wasm/` works as-is).
- `WclapHost.load(wasm, { extensions, onInstantiated })` — new options in
  `reference-host/host.mjs` for extra wasm imports + a post-instantiate hook.
- `renderRack({ ..., extensions })` — new option in `reference-host/rack.mjs`; when the
  source bundle has an extension entry, the source renders block-wise and the bridge's
  `drain()` is awaited after EVERY block, so async deliveries land at deterministic block
  boundaries and the offline render stays bit-deterministic.

## Build / test

```sh
node engines/cdp-engine/scripts/make-catalog.mjs   # regenerate catalog.json from third_party/cdp-wasm
EMSDK=~/emsdk bash engines/cdp-engine/scripts/build.sh   # -> build/module.wasm + cdp-engine.wclap.tar.gz
node --test tests/cdp-engine.test.mjs               # plugin level + bridge + examples/cdp-rack
node --test tests/                                  # whole suite
```

Example rack: `examples/cdp-rack/` (synth 'wave' sine arpeggio, key 69 = 440 Hz),
packed as `cdp-rack.wclap-rack.tar.gz` via `node tools/pack-rack.mjs examples/cdp-rack`.
MANIFEST sha256 is the sha of `module.wasm` inside the bundle (not of the tar.gz).

## Open / follow-ups

- Web app: serve the bridge inside the rack worklet (`packages/web` rack host) so
  `/wclap` can play cdp-engine racks live; the wasm assets are fetched lazily per program.
- Effects as rack stages: apply catalog effects offline at extract/QD time over the
  rendered source (bridge `applyEffectToWav`), e.g. in `tools/qd-rack.mjs`'s evaluate().
- Spectral effects (26 programs needing pvoc anal/synth) are the slow renders — cache
  per (program, params) and consider pre-rendering all keys at param change, like the
  CPPN engine's pre-rendered notes.
- cdp-plugin (iPlug3, Apache-2.0) already is a native CLAP/VST3/AU plugin embedding
  cdp-web — an alternative "port" for desktop DAWs, but it has no wasm target and would
  not run in a browser, so it is not the WCLAP path.
